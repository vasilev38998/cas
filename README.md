# CandyClub — аккаунтная игровая платформа

Проект вырос из отдельной демо-игры «Сладкий каскад» в полноценный PHP/MySQL-сайт с регистрацией, авторизацией, серверным виртуальным балансом, журналом операций и серверным расчётом игры.

## Стек

- PHP 8+
- MySQL / MariaDB
- PDO
- обычные HTML/CSS/JavaScript без Node.js и без сборки
- PHP sessions + HttpOnly/SameSite cookies
- `password_hash()` / `password_verify()`
- CSRF-защита форм и игрового API

Такой вариант рассчитан на обычный shared-хостинг вроде Beget: достаточно PHP и MySQL.

## Установка на хостинг

1. Создайте MySQL-базу и пользователя базы в панели хостинга.
2. Импортируйте файл `schema.sql` через phpMyAdmin или другой интерфейс MySQL.
3. Скопируйте `app/config.example.php` в `app/config.php`.
4. В `app/config.php` заполните `host`, `name`, `user`, `pass` от созданной базы.
5. Загрузите весь проект в корень домена. `.htaccess` уже задаёт `index.php` как главную страницу.
6. Откройте сайт и создайте первый аккаунт.

`app/config.php` добавлен в `.gitignore`, поэтому пароль базы не должен попадать в GitHub.

## Что уже работает

### Сайт

- главная страница с каталогом игр;
- регистрация по имени, email и паролю;
- авторизация и выход;
- защищённые PHP-сессии;
- аккаунт игрока;
- серверный виртуальный баланс в рублях;
- история начислений, ставок и выигрышей;
- стартовый виртуальный баланс для нового аккаунта.

### Сладкий каскад

- игра открывается только после авторизации;
- ставка и итог вращения рассчитываются на PHP-сервере;
- браузер больше не является источником истины для баланса;
- каждое списание и начисление записывается в `wallet_transactions`;
- каждый раунд записывается в `game_rounds`;
- прогресс игры хранится в `user_game_states`;
- поле 7×7, кластерные выигрыши и каскады;
- множители клеток до ×100;
- комбо длинных каскадов;
- «Сладкий взрыв» и «Сладкий шторм»;
- 8/10/12 фриспинов за 3/4/5+ бонусных символов;
- множители сохраняются во время серии фриспинов;
- медленная поколоночная анимация вращения и anticipation-эффекты;
- адаптация под мобильный portrait/landscape;
- звук через Web Audio API;
- отображаемая сумма каждого каскада уже является итоговой суммой после применённых игровых множителей — отдельно домножать её не нужно.

## Безопасность баланса

Изменение баланса выполняется внутри транзакции MySQL с `SELECT ... FOR UPDATE`. Ставка списывается и выигрыш начисляется сервером. Клиент получает уже рассчитанный результат и только проигрывает его анимацию.

Это намного надёжнее прежней версии на `localStorage`: изменение JavaScript или значения в DevTools не изменяет серверный баланс аккаунта.

## Добавление следующих игр

Общие таблицы `users`, `wallet_transactions` и `game_rounds` уже подходят для нескольких игр. Новую игру можно подключить отдельным `game_key` и собственным серверным endpoint, при этом регистрация, аккаунт и единый баланс останутся общими.

## Важно

Текущая версия использует **только виртуальный игровой баланс**. Реальные пополнения, вывод средств и платёжные системы намеренно не подключены. Для real-money эксплуатации дополнительно потребуются юридическая и регуляторная часть, KYC/AML, ограничения ответственной игры, сертифицированный RNG, аудит и инфраструктура платежей.
