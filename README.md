# CandyClub — игровая экосистема на PHP/MySQL

CandyClub — самостоятельная браузерная игровая платформа с аккаунтами, единым виртуальным балансом, серверным расчётом результатов, собственной библиотекой слотов, мини-играми, прогрессом игрока, ежедневным подарком, журналом операций и админ-панелью.

> Текущая версия использует только виртуальный баланс. Реальные платежи, вывод средств и платёжные провайдеры не подключены.

## Что входит в проект

### 10 оригинальных слотов

1. **Сладкий каскад** — 7×7, кластеры 6+, каскады, множители клеток до ×100, Сладкий шторм, Bonus Buy и Super Buy.
2. **Фруктовая фиеста** — 5×4, 8 линий, редкие wild/scatter, липкие wild во фриспинах, Bonus Buy.
3. **Храм тысячи путей** — 6×5, полные пути через 6/6 барабанов, каскады, растущая сила и перенос множителя во фриспинах.
4. **Джунгли: Золотой тотем** — 5×3, 6 линий, редкий Hold & Respin, фиксирующиеся монеты, Bonus Buy сразу в feature.
5. **Кристальный реактор** — 8×8, кластеры 7+, редкие бомбы 3×3, цепные каскады и фриспины.
6. **Свиток солнца** — 5×3, 6 линий, расширяющийся специальный символ во фриспинах.
7. **Неоновый разгон** — 5×5, полный путь 5/5, минимальная плотность совпадения, tumble и растущее напряжение.
8. **Небесный пантеон** — 6×5, 10+ одинаковых в любом месте, tumble, редкие сферы ×2–×100 и накопительный заряд во фриспинах.
9. **Бархатные шторки** — 5×4, физически закрывающиеся барабаны: один или два столбца накрываются шторкой и после паузы полностью раскрываются одним символом; во фриспинах feature усилен.
10. **Хранилище тайн** — 5×4, mystery-блоки: все тайные клетки одного вращения синхронно превращаются в один символ; во фриспинах mystery встречаются чаще.

У большинства слотов есть **Bonus Buy**. Покупка является отдельным серверным режимом, списывается из виртуального баланса, записывается в `game_rounds` и `wallet_transactions` и не рассчитывается на клиенте.

### 3 мини-игры

- **Плинко Лаб** — 12 рядов пегов. Сервер определяет путь и конечную ячейку, браузер только проигрывает траекторию шарика.
- **Кристальные мины** — поле 5×5, варианты 3/5/8/10 мин, растущий комбинаторный множитель и cash-out после любой безопасной клетки. Активная партия хранится в MySQL и переживает обновление страницы/смену устройства.
- **Колесо импульса** — 10 секторов с серверным выбором результата и плавной инерционной анимацией остановки.

### Игровая экосистема

- единый аккаунт и единый виртуальный RUB-баланс;
- уровень игрока и XP, рассчитываемые по игровой активности;
- лучшая победа и число раундов в профиле;
- ежедневный виртуальный подарок один раз в календарный день;
- избранные игры через localStorage;
- поиск и фильтры лобби;
- последние обезличенные выигрыши платформы;
- блок ежедневной активности;
- единый адаптивный интерфейс слотов;
- отдельные Big Win / Mega Win / Epic Win экраны;
- individual motion profiles, anticipation и процедурные WebAudio-звуки;
- прямые ссылки между слотами и мини-играми.

## Мобильные символы

Символы игровых полей рисуются собственными inline-SVG в `arcade-symbols.js`. Рендерер переписан без синтаксиса, который мог ломаться в старых мобильных Safari/WebView, и всегда имеет SVG-fallback вместо букв.

Все основные CSS/JS подключаются через `asset_url()`, который добавляет версию по `filemtime`. После обновления сервера мобильный браузер получает свежий `arcade-symbols.js`, а не старую закэшированную версию.

## Сладкий каскад

`game.php` больше не использует отдельный визуальный каркас. Игра переведена на тот же shell, что и остальные слоты: одинаковая верхняя панель, боковые блоки, поле, панель ставки, Spin/Auto/Turbo/Sound, навигация и адаптивность. При этом собственная кластерная математика, множители клеток, шторм, Bonus Buy и Super Buy сохранены.

## Серверная архитектура

- PHP 8.2+;
- MySQL/MariaDB;
- PDO с отключёнными emulated prepares;
- PHP sessions с HttpOnly/SameSite cookies;
- CSRF для форм и игровых POST API;
- серверный расчёт всех результатов;
- изменение баланса внутри MySQL-транзакций;
- `SELECT ... FOR UPDATE` на критичных операциях;
- журнал `wallet_transactions`;
- журнал `game_rounds`;
- состояние слотов и Mines в `user_game_states`;
- `password_hash()` / `password_verify()` для аккаунтов;
- cache-busting статических файлов;
- базовые security headers и отключённый directory listing через `.htaccess`.

## Админ-панель

`admin.php` доступен только аккаунтам, перечисленным в `app/config.php`:

```php
'app' => [
    // ...
    'admin_usernames' => ['my_admin_login'],
    'admin_emails' => ['admin@example.com'],
],
```

Админ видит количество пользователей и раундов, объём виртуальных ставок/выигрышей, последние раунды и новых пользователей. Можно корректировать только **виртуальный** баланс по логину или email. Каждая корректировка журналируется как `admin_adjustment`.

## Математика и тесты

`tools/simulate_math.php` прогоняет базовые вращения серверных slot-engine и показывает hit rate, feature rate, средний и максимальный результат тестовой выборки. Это инженерный инструмент балансировки, а не сертифицированный RTP-отчёт.

GitHub Actions автоматически выполняет:

- PHP lint для всех `.php`;
- `node --check` основных JS-файлов;
- smoke-test всех slot-engine, включая новые Curtains/Mystery;
- проверку математических helper-функций Mines;
- выборочную симуляцию slot math.

## Чистая установка

1. Создать MySQL/MariaDB базу.
2. Импортировать `schema.sql`.
3. Скопировать `app/config.example.php` в `app/config.php`.
4. Заполнить `host`, `name`, `user`, `pass`.
5. При необходимости указать `admin_usernames` или `admin_emails`.
6. Загрузить проект в корень сайта.
7. Использовать PHP 8.2+.
8. Открыть `/health.php` и убедиться, что окружение и БД доступны.
9. Создать обычный аккаунт через `/register.php`.

`app/config.php` находится в `.gitignore` и не должен попадать в публичный Git-репозиторий.

## Обновление существующей установки

Для обновления с предыдущей версии CandyClub:

1. Сделать резервную копию файлов и БД.
2. Загрузить/синхронизировать актуальный `main` поверх текущих файлов.
3. **Не удалять существующий `app/config.php`.**
4. В существующий `app/config.php` при желании добавить `admin_usernames` / `admin_emails`.
5. Текущий `schema.sql` повторно импортировать не требуется: новые функции используют существующие `users`, `wallet_transactions`, `game_rounds` и `user_game_states`.
6. Один раз открыть сайт в мобильном браузере заново. Статические файлы теперь имеют version query и должны обновиться автоматически; при наличии внешнего CDN его кэш лучше очистить.
7. Проверить `/health.php`, регистрацию/вход, один обычный слот, Bonus Buy, Plinko, Mines и Wheel.

## Что ещё потребуется для real-money продукта

Текущий код — продуктовая виртуальная игровая платформа, но **не готовый лицензированный real-money casino backend**. Перед подключением реальных пополнений/выводов отдельно потребуются юридическая модель и лицензирование в нужной юрисдикции, KYC/AML, responsible-gaming controls, возрастные ограничения, платёжный контур, antifraud, сертифицированный RNG/математика, независимый аудит, лимиты/самоисключение, журналирование регуляторного уровня и полноценный security review.

Не подключайте реальные платежи к текущему виртуальному игровому контуру без отдельного проектирования и аудита этих компонентов.
